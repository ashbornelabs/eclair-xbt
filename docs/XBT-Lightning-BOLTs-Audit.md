# XBT Lightning BOLTs source audit

## Purpose and limits

This is a source-based review of selected XBT Lightning requirements. The
pinned XBT BOLTs are the sole protocol authority. CLN and LND source is
comparison evidence only; their behavior does not define the protocol.

This review does not build or run CLN/LND, connect Lightning peers, open
channels, or send payments. It makes no live interoperability or general
compatibility claim. Those checks are tracked separately in GitHub issue #24.

## Normative requirements checked

- [BOLT #2: Peer protocol](https://github.com/lightning-blake2b/bolts/blob/1f3d88f79c46bd39d06114f23fbbafbff035938a/02-peer-protocol.md): channel-type negotiation, funding signatures, and unified-signature channel requirements.

The digest is defined by its explicit [unified-sighash reference](https://github.com/privkeyio/bitcoin/blob/54d757f269/doc/unified-sighash.md).
- [BOLT #7: Routing gossip](https://github.com/lightning-blake2b/bolts/blob/1f3d88f79c46bd39d06114f23fbbafbff035938a/07-routing-gossip.md#the-blake2b-activation-height): activation-height routing rules.
- [BOLT #9: Feature assignments](https://github.com/lightning-blake2b/bolts/blob/1f3d88f79c46bd39d06114f23fbbafbff035938a/09-features.md): feature contexts, dependencies, chain identity, and reader/writer requirements for the BLAKE2b marker.
- [BOLT #11: Payment encoding](https://github.com/lightning-blake2b/bolts/blob/1f3d88f79c46bd39d06114f23fbbafbff035938a/11-payment-encoding.md): invoice writer and payer requirements.
- [BOLT #12: Offers](https://github.com/lightning-blake2b/bolts/blob/1f3d88f79c46bd39d06114f23fbbafbff035938a/12-offer-encoding.md): offer, invoice-request, and invoice feature requirements.

## Findings and follow-up

Within the requirements and source paths listed above, this review found:

- no clear missing or ambiguous XBT BOLT requirement that warrants a report to the BOLTs maintainers;
- no source-supported CLN or LND discrepancy that warrants a report to either fork's maintainers;
- no new Eclair implementation defect to fix based on this review.

These are bounded source-review conclusions, not proof that every code path in
the three implementations conforms. In particular, no peers were built or run,
and no handshake, channel, invoice, or payment was exercised. Issue #24 remains
the place to record those runtime results next week.

## Review method

Compared the pinned BOLT clauses with the named source files at the immutable
revisions above. No tests or builds were run for this documentation-only
source audit.
